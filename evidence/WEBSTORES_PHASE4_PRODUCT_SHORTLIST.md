## Implementation and verification

Implemented: a read-only staff endpoint and an explained shortlist in the existing Products tab. Matches use visible frozen submitted/reviewed questionnaire answers and declared active template types/store suitability. The panel honors declined extras, flags unmatched requests, marks templates already selected and selects into the existing picker. It does not create a draft until staff uses the existing Add From Template action.

**Original verification:** 13 backend and 44 frontend tests passed for the shortlist. Owner visual review then correctly identified premature visibility of unsubmitted drafts. The corrected boundary has **22 focused backend tests and 21 frontend tests passing** across owner visibility, recommendations, product foundation, product/mockup approvals and launch-packet approval. Six new backend cases cover approval/request changes/rejection, private edits and resubmission, legacy evidence recovery, pending legacy edits, tenant/revoked access and protected submitted-image bytes. Frontend coverage checks the same submitted product collection feeds both owner lists and branding, the retained-version notice, approval controls and authenticated managed-media rendering without forwarding tokens to external image URLs. Normal GitHub CI is required on the updated draft PR; see its checks and local owner checklist for current results.

**Cause and correction (owner-authorized October 22):** owner detail previously returned all mutable product rows regardless of submission. The existing submission builder already produced an owner-safe snapshot and hash, but only the hash was retained on the product. Submission now retains that exact snapshot plus private image references on the same canonical product. Owner product lists and branding previews use one backend projection of this submitted evidence. Never-submitted products are omitted. Subsequent staff edits do not replace submitted content; the owner sees the previous version and a notice until staff explicitly resubmits. Canonical approval history and existing revision/hash decision guards remain in use. Duplicating a product strips submission evidence, so the copy starts private. Mockup decision responses cannot reveal an unsubmitted parent product and use the owner-safe allowlist. Existing launch packets remain frozen approved snapshots, and public eligibility rules are unchanged.

This correction receives Class C tenant/access-boundary verification: focused permission/content/compatibility tests, normal required CI and a critical staff-to-owner browser smoke. No broad local suite or repeated general audit was run.

**Legacy compatibility:** reuse canonical approval snapshots first; an unchanged record with existing submission/approval markers may supply verified current evidence, retained atomically before the first staff edit. If an older edited record has no recoverable submitted snapshot, hide it until staff resubmits rather than inventing its former contents. No live data migration or separate versioning store. Private image references from a historic already-edited row cannot be reconstructed if absent; existing stored image URLs remain subject to their original access rules until resubmission.

**Actual corrected browser verification:** normal staff/owner password authentication on run-owned isolated MongoDB/backend/frontend, dev bypass disabled and provider keys blank. Staff selected Hat from the recommendation and explicitly created its draft. Staff completed its name, description, SKU, uploaded demo image and manual $32 demo price, and saved it as Ready. A fresh owner read showed only the existing approved tee in both the product list and branding preview. Staff explicitly submitted Hat; the owner then saw Navy Hat, $32 and the authenticated submitted image, and successfully approved the product. Staff saved a private new name/description and $99 demo price without resubmitting. A fresh owner read retained Navy Hat, $32, the submitted image and approval history, with the last-submitted-version notice; neither private text nor $99 appeared. The original approved tee stayed intact. Request-changes/rejection/resubmission, public exclusion, legacy and authorization cases are covered by the focused API tests. No launch-packet approval, Terms acceptance, publishing, payment or provider action was performed. All prices are demonstration input, not Engine calculations or recommendation claims. Sample artwork is a synthetic local test fixture, not an AI-generated mockup.
