## Cause and affected paths

AI Studio bootstraps a local provider/model and billable capabilities. Its `run_tool` requested Gateway simulated success, then built local text/JSON without a provider call. Gateway treated that success as billable delivery and reserved/committed real included then purchased credits. Webstore description/mockup actions call this same Studio service. Existing Assistant local-contract actions also call the same Gateway with `ec18_assistant_local`. An arbitrary configured provider could previously receive simulated success through the public Gateway endpoint. A billable flag or estimated cost was not proof that a provider ran.

Affected scope is the shared local execution boundary: all AI Studio local catalog modes (including Webstore description and product mockup), Assistant local contract capabilities, and generic Gateway simulation requests. No capability prices, provider records or existing balances were migrated. Runtime enforcement covers previously bootstrapped billable records.

## Correction

- Shared `_execution_context` validates existing staff permissions, capability status/entitlement, allowed active model/provider and provider/model identity. Local classification uses trusted registered provider/model keys, intensity and local-execution metadata; no client flag determines billing. Known Studio and Assistant local providers remain classified locally even if old capabilities say billable.
- Local demonstrations are permitted only in explicitly configured `ENV=development` or isolated `ENV=test`. They have an effective customer charge of zero before reservation, even with no balance. Production rejects them before action execution/reservation, including idempotent cached requests. Action summaries identify nonbillable simulation; existing usage/cost/audit records are reused with zero simulated units/expenses and no credit-ledger debit/reservation.
- Unconnected provider profiles fail closed instead of synthesizing paid success. The public request schema no longer accepts `simulate_result`; forged `free`, `billable`, `provider_called`, `is_demo` or charge overrides cannot authorize delivery or alter charges.
- The existing capability charge, balance, governance, reservation/commit/release and idempotency functions remain authoritative. A trusted backend executor must verify successful delivery and a provider event before settlement; malformed/failed results release the reservation under the current accounting contract. No executor/provider is connected by this PR. EC16 accounting tests inject an in-process backend executor from `tests/ai_provider_contract.py`; this test helper is not imported by application code and is unavailable through request flags/configuration.
- Webstores preview obtains its effective charge and availability from the shared Gateway policy, and direct execution enforces the same policy without relying on preview. Existing confirmation still checks the exact displayed amount (zero for permitted demos). Production/unconnected execution has an unavailable reason and disabled execution button. The Studio catalog/UI identifies sample output, zero customer credits and unavailable production execution; no generated image is claimed. New Studio results persist their demonstration credit label. The existing Credits history labels new simulated rows as demonstrations without rewriting historical statuses.
- Current permissions/entitlements and request limits still apply. Idempotent replay is scoped to tenant/capability and rechecks current authorization/production availability. A historical charged demonstration is not silently replayed as free, refunded or rewritten; it returns a reconciliation explanation. Studio cached-result access also checks current execution policy and the referenced action before replay.
