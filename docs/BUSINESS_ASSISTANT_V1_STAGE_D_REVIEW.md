## Implementation and verification closeout

Implemented the authorized Stage D path within the existing Assistant. Browser WebRTC carries audio only; the authenticated backend exchanges SDP, controls the sideband, executes the same eight read tools, and saves provider-observed transcripts in the existing private conversation. Text/voice share bounded context, approved memory, source permissions and the single personality prompt. The existing full-page and floating interfaces share one session owner. Reconnect is explicit and starts a new metered session with saved context. No model write tools or autonomous actions were enabled.

Read tools now also support Orders due today/tomorrow and a bounded upcoming 30-day Schedule window/title query. Dates use the saved timezone; invoices retain the existing financial reconciliation service. Bounded or missing results never establish a shop-wide total or prove that no later installation exists.

Interruptions cancel generation and clear speaker playback. Generated transcripts that may contain unplayed words are marked, including interruption after generation finishes but before playback finishes. These messages remain visible as historical evidence but are excluded from future model context. Raw audio is not retained by this application. Provider retention is subject to the configured OpenAI account terms.

### Limits, security and operating setup

- Disabled by default. `ASSISTANT_REALTIME_ENABLED=true` and `OPENAI_REALTIME_ENABLED=true`, a backend API key and `ASSISTANT_VOICE_MODEL_PROFILE_ID` are all required. No real environment was activated here.
- Use an active allowed OpenAI `gpt-realtime-2.1` profile and active `assistant.voice_reply` capability. Profile metadata must explicitly list supported voices, a duration-priced `transcription_model` (`gpt-transcribe`, or legacy `whisper-1`), and sourced `realtime_pricing` rates: `input_text`, `input_audio`, `cached_text`, `cached_audio`, `output_text`, `output_audio` in USD/million tokens, plus `transcription_usd_per_minute`. Set `pricing_source` to the applicable documented rate sources. The documented duration event path is preferred; absent usage stops the session conservatively. No guessed production rates or bootstrap activation.
- Existing entitlements, employee permissions, shop credits and a daily provider-cost policy are required. A conservative full-session cost allowance and credits are reserved before dispatch. Default limits: 180 seconds/session, 45 seconds idle, 12 responses, 600 output tokens/response and 4,096 post-instruction context tokens. Configured values are clamped. Browser heartbeat loss, permission/source loss, disabled capability/configuration, budget reduction, input/response limits or unexpected provider events stop the session. The watchdog checks once per second; network/provider termination is not instantaneous.
- Provider-observed modality/cache tokens and separately observed transcription duration feed existing Gateway ledgers. **Money remains estimated from sourced rates; `actual_cost_micros` remains null.** A provider token count is not a verified provider invoice. Missing/in-flight usage retains conservative liability, including across midnight; observed cost exceeding the allowance raises the retained amount and stops further responses. Duplicate requests/events cannot redispatch or repeat accounting. Client-submitted voice billing is rejected.
- One text/voice turn owns a conversation at a time. Cross-user/shop session access is denied. Source and permission changes hide affected saved messages and stop active sessions. Backend-only credentials, no ephemeral key or provider data channel in the browser. Tools remain read-only and allowlisted. A focused primary-agent review corrected missing-usage continuation, interruption after generated output, in-flight speech accounting and startup lease timing; no unrelated refactor/audit.
- Persisted leases allow any worker to terminate stale known provider calls; shutdown closes active runtimes. Failed termination retains reservations and the conversation lock for recovery. Incomplete accounting/unknown provider-call outcome is visibly marked `recovery_required`; operator reconciliation remains necessary, with no automatic paid retry. This conservative operational limitation must be exercised against the actual account before launch.
- `.cache`, evidence, backend test harnesses and frontend tests remain excluded from production Docker context/build assets. The browser harness injects simulated media only in its disposable test process; no production bypass was added. Commercial preview recordings remain excluded.

## Six preview recordings: researched proposal, not executed

Keep the six downloaded documentation recordings excluded. Generate our own `alloy`, `ash`, `coral`, `echo`, `sage`, `shimmer` samples through the owner's authorized API account using **the same `gpt-realtime-2.1` model family** as conversations. No sample generation, API request or paid evaluation occurred.

Exact proposed procedure after separate authorization:

1. Confirm account terms/model access and approve a **$1 total ceiling**, six requests, one attempt per voice, with any retry requiring a new approval. Use a backend-only key and isolated generation process; no customer data, shop tools, microphone input or input transcription.
2. For each voice open `wss://api.openai.com/v1/realtime?model=gpt-realtime-2.1` with backend Bearer authorization. Send `session.update` with type `realtime`, `output_modalities:["audio"]`, `max_output_tokens:512`, `tools:[]`, `audio.input.transcription:null`, `audio.input.turn_detection:null`, and `audio.output:{voice:<id>,format:{type:"audio/pcm",rate:24000}}`. Instructions: read the supplied original script exactly in a neutral friendly tone, no additions. Wait for `session.updated`; error means stop, not retry.
3. Send `conversation.item.create` with a user `input_text` item: “Read exactly: Hi, I'm your AI assistant at SignGuy. I can help you find shop information, review order status, and plan your next step.” Send exactly one `response.create`. Collect `response.output_audio.delta` PCM bytes and generated transcript. On `response.done`, record usage, stop on missing/failed usage and close the WebSocket. No conversational loop or paid preview on customer clicks.
4. Wrap PCM as mono, 16-bit, 24-kHz WAV; verify format, duration, complete exact speech and no unintended additions. Record model, voice, request/response ID, UTC date, original script, generation parameters, usage/rates, estimated cost, SHA-256, applicable account terms/version and generation ownership. Do not include the key. Review all six files before bundling.
5. Replace local-only documentation clips with the newly generated files, update provenance/catalog and run existing free-playback tests. Display “AI-generated voice preview” beside playback. Check the terms actually applicable to that API account at generation time. Only then resolve C's release requirement; do not mark the current unlicensed clips cleared.
